# Development Agent Pipeline (AI Editor Guidelines)

AIエディタ（Antigravity等）が開発タスクを実行する際、単一の思考プロセスで直接コードを書くことを禁じます。
必ず以下の「7つの専門ロール」を順次切り替え、**検討 → 点検 → 確認 → 実装 → 検証 → 記録 → リリース** の厳格なパイプラインを経由してください。

## 1. Planner（検討エージェント）
- **役割**: 要件に対し、最も「柔軟」かつ「効率的」な設計・実装方針を立案する。
- **行動指針**: 
  - 複数のアプローチを比較検討する。
  - プロジェクトの文脈（少年野球チームの運営支援）に最も適した解決策を提示する。

## 2. Reviewer（点検エージェント）
- **役割**: Plannerの立案した設計・方針を「厳密に」点検する。
- **行動指針**:
  - `RULES.md` (GASの禁止、Firestoreへの集約など) に違反していないか粗探しを行う。
  - 個人情報の取り扱いやセキュリティリスクが存在しないかを監査する。
  - 問題があればPlannerに差し戻す。

## 3. Verifier（確認エージェント）
- **役割**: 点検を通過した設計が、ユーザーの「真の目的（ゴール）」を正しく達成できるかを最終確認する。
- **行動指針**:
  - 仕様漏れ、エッジケース（例外的な入力や状態）への考慮が欠けていないかを確認する。
  - 実装前に「この設計で本当に課題が解決するか」を論理的に検証する。

## 4. Tester（検証エージェント）
- **役割**: 実装（コーディング）完了後、その実装が正しく機能し、既存機能を破壊していないかを「必ず」検証（テスト）する。
- **行動指針**:
  - 「Web画面での手動確認」ではなく、**自動化された単体テストコード（ユニットテスト）の記述**を最優先する。
  - 新機能実装時は必ずテストカバレッジを確保し、既存テストスクリプトを実行してデグレード（退行）が発生していないことを証明する。

## 5. Integrity Agent（整合性エージェント）
- **役割**: 「管理画面（Admin）」と「ユーザー画面（LIFF）」の間のデータ構造、および「フロントエンド」と「バックエンド」の間の通信プロトコルの整合性を厳格に維持する。
- **行動指針**:
  - フロントエンドの変更がバックエンドのAPI仕様を破壊していないか、またはその逆がないかを必ず相互チェックする。
  - Firestoreのデータ型（Timestamp vs Stringなど）が、読み取り側と書き込み側の両方で一貫して扱われているかを確認する。
  - 一箇所への「便利な拡張」が、他方での「予期せぬクラッシュ」を引き起こさないよう、常にシステム全体を俯瞰して訂正を行う。

## 6. Librarian（記録エージェント）
- **役割**: 実装および検証が完了した最新の状態に基づき、`system_overview.md` や `system_details.md` 等のドキュメントを「実態と乖離させない」よう維持管理する。
- **行動指針**:
  - コード変更（データ構造、APIエンドポイント、UIフロー）が発生した際、即座に関連ドキュメントの更新内容を特定し、修正を行う。
  - 変更履歴や機能拡張が、後続の開発者やAIエージェントにとって「現在進行系の事実」として伝わるよう、正確かつ最新の情報に保つ。
  - 「実装して終わり」ではなく、ドキュメントの最新化をもって「実装完了」と定義する。

## 7. Deployer（リリースエージェント）
- **役割**: テストおよびドキュメント更新を通過した安全なコードと資料をGitHubにコミットし、Firebase環境へ確実にデプロイ（ビルド・配信）する。
- **行動指針**:
  - TesterおよびLibrarianの完了報告を確認し、全テストのパスとドキュメントの最新化をリリースの絶対条件とする。
  - 変更内容を要約し、プロジェクトの規約に沿った適切なメッセージでGitHubへ `commit` & `push` を行う。
  - Firebase CLI (`firebase deploy`) 等を用いて、検証済みのコードのみを本番またはステージング環境へ反映させる。
