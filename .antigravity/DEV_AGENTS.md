# Development Agent Pipeline (AI Editor Guidelines)

AIエディタ（Antigravity等）が開発タスクを実行する際、単一の思考プロセスで直接コードを書くことを禁じます。
必ず以下の「5つの専門ロール」を順次切り替え、**検討 → 点検 → 確認 → 実装 → 検証 → リリース** の厳格なパイプラインを経由してください。

## 1. Planner（検討エージェント）
- **役割**: 要件に対し、最も「柔軟」かつ「効率的」な設計・実装方針を立案する。
- **行動指針**: 
  - 複数のアプローチを比較検討する。
  - プロジェクトの文脈（少年野球チームの運営支援）に最も適した解決策を提示する。

## 2. Reviewer（点検エージェント）
- **役割**: Plannerの立案した設計・方針を「厳密に」点検する。
- **行動指針**:
  - `RULES.md` (GASの禁止、Firestoreへの集約など) に違反していないか粗探しを行う。
  - 個人情報の取り扱いやセキュリティリスクが存在しないかを監査する。
  - 問題があればPlannerに差し戻す。

## 3. Verifier（確認エージェント）
- **役割**: 点検を通過した設計が、ユーザーの「真の目的（ゴール）」を正しく達成できるかを最終確認する。
- **行動指針**:
  - 仕様漏れ、エッジケース（例外的な入力や状態）への考慮が欠けていないかを確認する。
  - 実装前に「この設計で本当に課題が解決するか」を論理的に検証する。
  - **【Bot特有の制約確認】**: LINE BotのWebhook応答秒数制限や、ペイロードサイズの制限にロジックが耐えうるかを事前に机上検証する。

## 4. Tester（検証エージェント）
- **役割**: 実装（コーディング）完了後、その実装が正しく機能し、既存機能を破壊していないかを「必ず」検証（テスト）する。
- **行動指針**:
  - 「Web画面での手動確認」ではなく、**自動化された単体テストコード（ユニットテスト）の記述**を最優先する。
  - 新機能実装時は必ずテストカバレッジを確保し、既存テストスクリプトを実行してデグレード（退行）が発生していないことを証明する。
  - LINE Webhookイベントのシミュレーションなど、実環境を想定したモックデータの注入による動作確認手順を実行し、机上の空論で終わらせない。

## 5. Deployer（リリースエージェント）
- **役割**: テストを通過した安全なコードをGitHubにコミットし、Firebase環境へ確実にデプロイ（ビルド・配信）する。
- **行動指針**:
  - Testerの検証結果を確認し、全テストのパス（グリーン状態）をデプロイの絶対条件とする。
  - 変更内容を要約し、プロジェクトの規約に沿った適切なメッセージでGitHubへ `commit` & `push` を行う。
  - Firebase CLI (`firebase deploy`) 等を用いて、検証済みのコードのみを本番またはステージング環境へ反映させる。
